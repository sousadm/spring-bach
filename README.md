# Spring Batch — Importação de CSV para PostgreSQL

Projeto Spring Boot que utiliza **Spring Batch** para ler um arquivo CSV e importar os registros para uma tabela no banco de dados **PostgreSQL**.

---

## 📋 O que o projeto faz

1. Ao iniciar, o Spring Batch executa automaticamente o job `importUserJob`
2. O job lê o arquivo `pessoas.csv` (localizado em `src/main/resources`)
3. Cada linha do CSV é mapeada para um objeto `Person`
4. Os registros são inseridos em lote na tabela `person` do PostgreSQL

## ⚙️ Fluxo do Spring Batch

```
pessoas.csv
    │
    ▼
FlatFileItemReader        ← lê linha por linha, pulando o cabeçalho
    │
    ▼
PersonItemProcessor       ← processa/transforma o objeto (passthrough neste projeto)
    │
    ▼
JdbcBatchItemWriter       ← insere em lotes de 10 registros no PostgreSQL
    │
    ▼
Tabela person (PostgreSQL)
```

O Step é configurado com `chunk(10)`, ou seja, a cada 10 registros lidos e processados, um `INSERT` em lote é enviado ao banco.

---

## 🗄️ Formato do CSV

O arquivo `pessoas.csv` deve ter cabeçalho na primeira linha e as colunas na seguinte ordem:

```csv
nome,email,idade
João Silva,joao@email.com,30
Maria Souza,maria@email.com,25
```

---

## 🗃️ Tabelas criadas no banco

O Hibernate cria automaticamente a tabela de negócio, e o Spring Batch cria as tabelas de metadados:

**Tabela de negócio:**
```sql
CREATE TABLE person (
    id    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome  VARCHAR(255),
    email VARCHAR(255),
    idade INTEGER
);
```

**Tabelas de metadados do Spring Batch** (criadas automaticamente via `spring.batch.jdbc.initialize-schema=always`):
- `batch_job_instance`
- `batch_job_execution`
- `batch_job_execution_params`
- `batch_job_execution_context`
- `batch_step_execution`
- `batch_step_execution_context`

## 🔧 Configuração

Edite o arquivo `src/main/resources/application.properties` com as credenciais do seu banco:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/teste
spring.datasource.username=postgres
spring.datasource.password=sua_senha
```

Certifique-se de que o banco de dados `teste` existe antes de iniciar a aplicação.

## ▶️ Como executar

### Pré-requisitos

- Java 21+
- Maven 3.8+
- PostgreSQL em execução com o banco `teste` criado

### Executar

```bash
mvn spring-boot:run
```

A aplicação executa o job automaticamente na inicialização e **encerra o processo assim que o job termina**. Não há servidor web — o comportamento é o de uma aplicação batch de linha de comando.

---

## ⚠️ Observações importantes

**`@EnableBatchProcessing` não deve ser usada com Spring Boot 3+.**
No Spring Boot 3, o auto-configure do Batch já configura o `JobRepository`, `JobLauncher` e a inicialização do schema automaticamente. Usar a anotação desabilita esse comportamento e impede a criação das tabelas de metadados.

**Reexecução do job:**
O Spring Batch identifica execuções pelo conjunto de parâmetros do job. Ao executar com `JobParameters` vazios, o job só roda uma vez — execuções subsequentes são ignoradas por já constarem como `COMPLETED`. Para forçar uma nova execução, passe um parâmetro único como timestamp.
